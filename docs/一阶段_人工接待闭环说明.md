## 1. 本次合并交付

本次将仓库从业务文档阶段推进为可以本地运行的文字人工接待应用：用户留言并主动转人工，商家查看、接手、在同一会话回复、结束处理；后续咨询保留历史和用户再次选择人工的权利。

| 交付 | 已完成内容 |
|---|---|
| 用户页 | 免注册会话、文字发送、状态提示、主动转人工、历史记录和新消息提示 |
| 商家工作台 | 密码登录、待处理／已结束列表、聊天记录与交接信息三栏、接手／回复／结束 |
| 后端与存储 | FastAPI 接口、MySQL 会话与消息持久化、交接轮次、事务和重复请求去重 |
| 身份与权限 | 独立访客和商家会话、密码哈希、HttpOnly Cookie、来源与 CSRF 校验、登录限流与退出 |
| 同步与失败处理 | 约两秒轮询、操作后刷新、已读范围、新消息提示、断网保留输入、响应丢失后安全重试 |
| 本地工程 | 项目内 MySQL、配置示例、依赖锁文件、启停工具、独立测试库与测试端口 |
| 文档与验证 | 本文统一说明、9 项 MySQL 集成测试、Edge 浏览器闭环和前端生产构建 |

只支持文字，不上传或处理图片／视频。没有模型 API 调用、RAG、真实 AI 回答或交接摘要；页面明确显示尚未接入。未接真实支付、订单或物流，不自动批准退款、换货或赔偿。未部署公网，尚无真实用户效果数据。

## 3. 会话流程与页面行为

| 状态 | 用户页 | 商家操作 |
|---|---|---|
| `ai_ready` | 可留言，AI 尚未接入，可主动转人工 | 新访客尚未转交时不在商家列表；已有结束交接仍归已结束记录，不能回复 |
| `waiting_human` | 等待人工，可补充文字，不重复申请 | 查看、接手；接手前不能回复或结束 |
| `human_active` | 人工接待中，双方可发文字 | 回复、结束；重复接手不重复写系统事件 |
| `ended` | 本次已结束，历史保留，可再留言或主动转人工 | 已结束列表查看，不能继续回复 |

**每一轮咨询均保留用户主动选择。** 结束后新留言只恢复 `ai_ready`，不会默认申请人工，也不会创建新交接。用户主动点击“转人工”后，才将原会话移回待处理并递增交接轮次，商家须重新接手后回复。也可以结束后直接点击转人工，无需先留言。

查看只清除实际看到的消息对应的未读状态，不会接手、结束或改变列表归属。上一轮结束时间、交接与聊天历史保留；同一会话同时最多一条未结束交接，重复转人工或同时提交请求不会重复开单。

用户页首次自动取得本人会话；不要求姓名、手机号或订单号。用户／商家／系统事件以身份文字区分。凭证失效后明确提示建立新会话，不静默换成其他人的记录。

商家登录后显示三栏：左栏待处理与已结束，中栏完整记录和回复区，右栏本次交接原因、时间、记录覆盖范围与接手／结束按钮。首次不默认选中会话。AI 摘要只显示“尚未接入”，不会把占位内容伪装成业务结论。

阅读历史时不强制滚到底部；新消息提示可跳至最新位置。手机用户页和商家小屏布局可使用。发送中阻止重复点击，失败保留输入，重试复用消息编号；接手和结束只在服务端确认成功后更新。

## 4. 数据、接口与权限

| 表 | 用途 |
|---|---|
| `conversations` | 当前状态、连续消息序号、revision、创建／更新时间 |
| `messages` | 用户、商家文字与系统事件；会话内序号及发送编号唯一 |
| `handoffs` | 每轮交接原因、覆盖序号、接手／结束时间、已读序号与查看标记 |
| `visitor_sessions` | 访客令牌摘要、所属会话、CSRF 摘要和过期时间 |
| `merchant_accounts`、`merchant_sessions` | 单商家密码哈希及独立登录会话 |

访客 Cookie 默认 30 天，商家登录默认 8 小时。服务端只保存会话令牌与 CSRF 的摘要；商家密码使用带随机盐的 PBKDF2 哈希。Cookie 为 HttpOnly、SameSite Strict；本地未启用 Secure，公网部署前必须配置 HTTPS 与安全 Cookie。

| 接口 | 行为 |
|---|---|
| `POST /api/visitor/session` | 首次创建本人会话；有效凭证复用会话并轮换操作令牌 |
| `POST /api/visitor/reset` | 明确清除失效的本浏览器凭证，不删除旧记录 |
| `GET /api/visitor/conversation` | 返回本人公开状态与完整消息，不接受会话 ID 越权读取 |
| `POST /api/visitor/messages` | 保存文字，新咨询不自动转人工 |
| `POST /api/visitor/handoff` | 主动转人工，幂等创建当前交接 |
| `POST /api/merchant/login`、`GET /api/merchant/session`、`POST /api/merchant/logout` | 登录、恢复登录态、退出 |
| `GET /api/merchant/conversations` | 待处理和已结束两列表，含最近消息、状态和未读 |
| `GET /api/merchant/conversations/{id}` | 登录后查看完整记录和当前交接，不隐式接手 |
| `POST /api/merchant/conversations/{id}/read` | 按当前交接及已显示序号标记已读 |
| `POST /api/merchant/conversations/{id}/takeover` | 接手当前交接，旧轮次操作拒绝 |
| `POST /api/merchant/conversations/{id}/messages` | 仅人工接待中能回复 |
| `POST /api/merchant/conversations/{id}/end` | 接手后结束本轮，保留历史 |
| `GET /api/health` | 应用健康入口；启动工具另做数据库连接检查 |

消息为 1—2000 字，去除首尾空白，拒绝空内容或额外伪造角色字段；`client_message_id` 用于去重。写操作需同源和 CSRF 校验。会话修改使用数据库行锁及事务；旧页面的已读回执不能吞掉新消息，重复请求不重复保存。

当前读取完整消息；列表最多返回最近 200 个已有交接的会话，演示会话消息上限为 2000。尚未实现分页或增量消息接口，这些是未来扩展项。用户接口不返回交接对象、内部规则或商家凭据；角色入口本身不授予权限。

## 5. 本地运行

适用于 Windows PowerShell，命令从项目根目录运行。本机已经安装依赖并准备项目内 MySQL，只监听 `127.0.0.1:3307`，不注册系统服务。

### 已准备电脑的启停

```powershell
.venv\Scripts\python.exe -X utf8 scripts/start_mysql.py
.venv\Scripts\python.exe -X utf8 scripts/start_dev.py
```

MySQL 已运行时无需再次启动；端口已占用时脚本拒绝重复启动。用户页 `http://localhost:5173`，商家页 `http://localhost:5173/merchant`。统一使用 `localhost`，与 `APP_ORIGIN` 校验一致，不混用 `127.0.0.1:5173`。

| 本机文件 | 用途 |
|---|---|
| `.local/merchant-login.txt` | 本机生成的商家账号密码，不提交或转发到聊天 |
| `backend/.env` | 应用数据库与允许来源配置，不提交 |
| `.local/mysql-root-password.txt` | 本机 MySQL 管理凭据，不提交 |
| `.local/mysql-data/` | 正式与测试库数据，不提交 |
| `.local/api.log`、`.local/web.log` | 正常服务日志 |
| `.local/mysql-data/*.err` | MySQL 实际服务日志 |

停止服务：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-dev.ps1
.venv\Scripts\python.exe -X utf8 scripts/stop_mysql.py
```

前后端停止工具核验保存的 PID 命令属于当前项目后才停止，不批量结束所有 Python／Node 进程。MySQL 工具检查实际进程路径，正常关闭并等待进程退出，避免立即重启遇到文件锁；不删除数据。重启电脑后需重新启动。

### 首次安装或新电脑

需要 Node.js 22、Python 3.13 和网络。

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
npm --prefix frontend ci

# 下载官方 MySQL 8.4.11 ZIP、核验、解压、初始化并设置随机密码。
# 下载约数百 MB；已有.env或数据时不覆盖，不注册系统服务。
.venv\Scripts\python.exe -X utf8 scripts/setup_mysql.py

$env:PYTHONPATH='backend'
.venv\Scripts\python.exe -X utf8 -m app.init_db
.venv\Scripts\python.exe -X utf8 -m app.create_merchant --generate
.venv\Scripts\python.exe -X utf8 scripts/start_dev.py
```

发行包来自 [MySQL 官方下载站](https://dev.mysql.com/downloads/mysql/8.4.html)，本机已核验官方 MD5：`2e833921898a9a030ea6bfe81bd811bc`。随机凭据写入上表的本机忽略文件，不输出到终端。

本机 npm 官方下载曾出现证书链错误；可保持 TLS 验证执行 `npm --prefix frontend ci --registry=https://registry.npmmirror.com`，不要关闭证书验证。

初始化创建缺失表并增量补充 `handoffs.viewed` 列，不删除已有记录。生产迁移和备份尚需完善。旧版本若有未接手的自动交接，可执行以下工具恢复用户选择；主动申请及正在接待的会话保留：

## 7. 演示与后续

1. 用户发送文字，主动点击“转人工”。
2. 商家查看待处理；只清已读，此时不能回复。
3. 接手后回复，用户约两秒内收到。
4. 商家结束，会话归已结束，历史保留。
5. 用户再留言，保持普通咨询；再次主动转人工后回待处理，轮次递增，商家重新接手。

下一步共同确定约 10 人远程试用的平台和预算，补齐 HTTPS、安全 Cookie、同源反向代理、进程运行、数据库备份与恢复。当前开发服务器仅用于本地预览。

二阶段再核实并接入 DeepSeek 官方接口、公开知识检索、真实交接摘要和 AI 请求状态控制，执行业务题与流程回归。当前不购买托管资源、不运行付费模型。
