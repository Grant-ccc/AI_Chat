# 花窗伞 AI 客服 MVP

基于音乐剧花窗伞团购经历的 AI 客服产品实践项目，以第二轮团购为历史模拟场景，探索通过准确的商品答疑和人工交接，改善重复咨询与客服接待体验。

当前处于**模型比对开发题复核阶段**。已通过学校 API 完成三个候选模型各六题的两轮调用，共 36 次，详见[首轮结果](./模型比对_首轮结果_2026-10-09.md)和[v2 复测报告](./模型比对_第二轮结果_2026-10-09.md)。尚未最终选型、实现网页或上线；没有真实咨询下降或节省工时数据，离线回复不代表人工交接流程已可用。

## 产品范围

- **售前答疑为主**：回答晴雨使用、印刷防水、材质、款式与价格等问题，说明信息来源和未知边界。
- **使用说明与人工交接为辅**：必要时追问；涉及退款、换货、赔偿、责任判断或规则例外时转人工。
- **用户与商家双页面**：计划共享同一会话记录；商家工作台采用会话列表、聊天记录、处理摘要三栏布局。
- **人工接待闭环**：转交后 AI 暂停回复，商家接手并在原会话回复，结束后由 AI 接待后续问题。内部摘要仅商家可见。

第一版不接真实支付、订单或物流，不由 AI 审核售后视频，也不自动批准退款、换货或赔偿。使用视频先以明确标识的占位入口呈现。

## 模型比对计划

通过学校提供的统一 API 比较 DeepSeek-V4-Flash、Qwen3.5-Flash 和 Qwen3.5-Plus，候选尚未实测或最终选定。准确模型 ID 和可用参数在首次调用时核实。

首轮拟使用 T01、T04、T07、T10、T15、T17 六道开发题，以相同公开知识和问题比较默认配置下的表现。先验证单个模型的一次调用，再扩大测试范围。优先检查事实与来源、处理动作、交接边界和表达，再比较耗时及返回用量；结果由人工复核。

- T01—T20 为开发集，T21—T30 为保留集；参考答案和保留题不进入日常调试提示。
- 商家内部规则不进入用户回答知识。
- **T04 的已确认要求**：没有防晒检测报告时，直接说明无法确认 UPF50+，不自动转人工，也不推断商品一定未达标。
- 离线模型回复不能证明网页转交、消息权限或人工接待流程已实现，流程验收需在网页开发后单独执行。

## 接入条件与后续步骤

新增 [开发集扩展测试说明](./开发集扩展测试说明.md)：`extended_test.py` 对剩余13题比较 DeepSeek 与 Qwen Flash，共26次调用，包含固定多轮上下文，不包含T19或保留题。默认不联网，实际运行使用 `python -X utf8 extended_test.py --run`；目前已完成本地检查，实际结果待运行后复核。

学校 API 需要校园网或学校 VPN，不能假设外部云服务器可以直接访问。API Key 只在本地配置，不写入代码、文档或仓库。已有 Python 标准库脚本 `test_model.py`（T04 单题）和 `batch_test.py`（六题、三个模型，probe-v2）；默认不联网，添加 `--run` 才实际调用，使用本地环境变量 `SDU_API_KEY`。原始输出保存在被 Git 忽略的 `results/`。

1. 核对模型 ID，准备本地网络与凭据，验证一次调用。
2. 完成首轮小范围比对，再运行开发集并记录实际结果。
3. 根据结果选择模型、冻结配置，用保留集检查。
4. 确定身份、存储及材料接收方式，先实现人工闭环，再接 AI。

开发与调用按确认的步骤逐步推进。业务规则详见项目文档；本项目的历史模拟说明不代表当前实际销售、物流或售后承诺。
