# 花窗伞 AI 客服 MVP

基于花窗伞团购经历的客服产品实践，以第二轮团购为历史模拟场景。售前答疑为主，使用说明和人工交接为辅；不接真实支付、订单物流，不自动批准退款、换货或赔偿。

当前分支为 **stage-one-planning**，正在共同确定人工接待闭环的技术栈和实现规范，尚未开始网页开发。

## 本阶段目标

用户与商家共享同一会话：发送消息、主动转人工、商家查看和接手、在原会话回复、结束处理、后续再次咨询。商家工作台采用会话列表、聊天记录、交接信息三栏布局。

身份、权限、持久化和未读状态由后端处理。AI回答与摘要先明确占位，二阶段再接入DeepSeek官方接口。

## 技术规划

- 前端：React＋TypeScript＋Vite，用户已确认。
- 后端：Python＋FastAPI，用户已确认。
- 数据库：MySQL，用户已确认。
- 访问方式：首轮约10人远程试用；先本地开发验收，再部署同一套应用。暂无服务器，可稍后租用，接受少量托管费用，平台与费用上限待定。
- 登录、消息同步、附件范围和托管方案：讨论中，不视为已确定。

## 分支用途

本分支只保留产品业务材料和一阶段规划。模型筛选脚本、提示实验稿及结果报告保留在 [model-comparison分支](https://github.com/Grant-ccc/AI_Chat/tree/model-comparison)，不放入当前文件树。

学校API用于多模型筛选，产品后续拟接DeepSeek官方接口；官方模型ID、配置与行为届时需重新核对并回归测试。暂无可运行网页，当前不提供启动命令或宣称实际客服效果。

凭据、环境配置、数据库及原始聊天测试输出不提交仓库。
