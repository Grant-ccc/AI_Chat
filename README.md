# 花窗伞 AI 客服 MVP

基于花窗伞团购经历的客服产品实践，以第二轮团购为历史模拟场景。售前答疑为主，使用说明和人工交接为辅；不接真实支付、订单物流，不自动批准退款、换货或赔偿。

一阶段文字人工接待已实现，并完成本地验证；AI 回答和真实摘要尚未接入，暂无公网部署。

## 本阶段目标

用户与商家共享同一会话：发送消息、主动转人工、商家查看和接手、在原会话回复、结束处理、后续再次咨询。商家工作台采用会话列表、聊天记录、交接信息三栏布局。

身份、权限、持久化和未读状态由后端处理。AI回答与摘要先明确占位，二阶段再接入DeepSeek官方接口。

## 本地使用

本机已经准备项目内 MySQL、Python 环境与前端依赖。在项目根目录执行：

```powershell
# MySQL 已运行时无需重复执行；提示端口已占用时先确认现有进程。
.venv\Scripts\python.exe -X utf8 scripts/start_mysql.py
.venv\Scripts\python.exe -X utf8 scripts/start_dev.py
```

用户页：[http://localhost:5173](http://localhost:5173)；商家页：[http://localhost:5173/merchant](http://localhost:5173/merchant)。统一使用 `localhost`，与本地允许来源配置一致。

商家账号密码保存在本机 `.local/merchant-login.txt`，不会提交。完整安装、停止和测试步骤见 [一阶段人工接待闭环说明](./docs/一阶段_人工接待闭环说明.md)。本阶段不需要模型 API Key。

## 技术与边界

- 前端：React＋TypeScript＋Vite，用户已确认。
- 后端：Python＋FastAPI，用户已确认。
- 数据库：MySQL，用户已确认。
- 访问方式：首轮约10人远程试用；先本地开发验收，再部署同一套应用。暂无服务器，可稍后租用，接受少量托管费用，平台与费用上限待定。
- 身份：用户免注册、浏览器保存会话凭证；单商家账号密码登录。
- 同步与附件：约两秒轮询，发送后立即刷新；一阶段仅文本，不上传或处理图片／视频。
- 托管平台、预算上限及生产备份方案：仍待确定。

访客用 HttpOnly Cookie 绑定自己的记录；商家必须接手后才能回复和结束。结束后新留言恢复普通咨询，保留用户主动选择；只有再次点击“转人工”才开启下一轮交接并回到待处理，复用原会话，商家须重新接手。失败保留输入，同一消息重试不重复保存；用户接口不返回商家交接信息。

## 验证

9 项真实 MySQL 集成测试通过；Edge 浏览器闭环通过，包括新咨询保留用户主动转人工的选择、响应丢失重试、断网保留输入、历史阅读时的新消息与未读标记、访客隔离、退出登录及手机布局。前端生产构建通过。验收范围见 [阶段说明](./docs/一阶段_人工接待闭环说明.md#6-测试与验收)。这些结果不等同于模型正确率或真实用户试用效果。

## 本地检索对照（尚未接入聊天）

已新增数据驱动的 BM25 字面检索与本地中文语义检索工具。仅查找公开依据，不生成回答，不创建人工事项，不访问订单或聊天数据库。商品组合独立保存，内部规则和测试答案不进入索引。更换符合相同格式的知识文件可使用 `--knowledge`，核心检索算法不含花窗伞专用词典。

```powershell
# 可选依赖，人工接待服务不需要安装。语义检索首次运行需联网下载公开模型。
.venv\Scripts\python.exe -m pip install -r backend/requirements-retrieval.txt
# 业务 Markdown 是事实来源；修改知识后重新导出，并检查是否一致。
.venv\Scripts\python.exe -X utf8 scripts/export_public_knowledge.py
.venv\Scripts\python.exe -X utf8 scripts/export_public_knowledge.py --check
# 同一道问题对照两个方法；也可选择 --method keyword，无需向量模型。
.venv\Scripts\python.exe -X utf8 scripts/retrieval_probe.py --query "防晒伞下雨能用吗？"
# 多轮已知信息由调用者提供；此工具尚未实现真实会话上下文管理。
.venv\Scripts\python.exe -X utf8 scripts/retrieval_probe.py --query "不会收，有教程吗？" --context "我买的是自动款"
# 开发题验证，默认前3条候选。模型已缓存后可添加 --local-only，避免下载。
.venv\Scripts\python.exe -X utf8 scripts/retrieval_probe.py --evaluate --local-only
```

模型为 `BAAI/bge-small-zh-v1.5`，FastEmbed 0.7.4 / ONNX 在本机 CPU 运行，无付费 API 调用；模型缓存和逐题结果位于被 Git 忽略的 `.local/embedding-models` 与 `.local/retrieval`。首次下载约90 MB，详情见 [FastEmbed 官方模型清单](https://qdrant.github.io/fastembed/examples/Supported_Models/)。`--model` 可以更换 FastEmbed 支持的模型，不表示所有模型都适合中文。

2026-10-09 首轮对照使用同一份28条公开条目、18道构造开发题和5道新增无关题，未使用T21—T30保留题，也未扩充专用同义词或调整匹配阈值。评测问题保留原开发题输入栏中的已知上下文说明；这些不是实际用户输入样本。

| 前3条候选的检查项 | BM25 字面检索 | 中文语义检索 |
|---|---|---|
| 找全全部预期依据 | 11/18题 | 12/18题 |
| 每题预期依据召回比例的平均值 | 70.37% | 75.93% |
| 5道无关题中返回了候选的题数 | 0/5 | 5/5 |

以上不是回答正确率；预期编号用于核对，不代表唯一可用资料。该轮语义模型改善了雨天使用和材质题，但图案防水、收伞和故障原因题仍有漏检，不能推导语义检索普遍优于字面检索。语义检索按相似度总会返回候选，当前 `sufficiency=unvalidated`，未校准资料充分性阈值，分数不等于可信度，两种分数也不能直接比较。默认日期仅作为报告元数据，尚未实现日期推理。

7项独立测试通过：源文档与公开导出一致、拒绝非公开条目、替换饮品知识后算法照常运行、无关字面查询不强行返回、缺失报告本身可检索、开发题范围及多轮输入、指标计算。测试不需要数据库或模型下载；临时目录需位于可写位置。下一步检查漏检原因，讨论混合检索与资料不足的判断，再决定是否接入客服回答。

### 混合检索与资料缺口诊断（2026-10-09）

新增 `--method hybrid` 和 `--method all`。混合检索使用 RRF，按两路候选的名次合并，不直接相加 BM25 与余弦分数；同一编号只返回一次，并保留两路名次和原分数供检查。公式与排序概念参考 [Elastic 官方 RRF 文档](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)，本项目在Python中实现，未安装 Elasticsearch。实验参数为每路前10条、排序常数60、最终前3条，可通过 `--rank-window` 与 `--rank-constant` 修改；这些参数尚未调优。

```powershell
.venv\Scripts\python.exe -X utf8 scripts/retrieval_probe.py --evaluate --method all --local-only --diagnose-gaps
```

主评测沿用同一份知识和原18道开发题、5道无关题。混合检索找全预期依据 **13/18题**，平均预期依据召回比例 **78.70%**；字面检索仍为11/18、语义仍为12/18。无关题的混合候选仍为5/5。`all` 模式共享已初始化的向量模型，混合步骤的初始化耗时不能当作独立冷启动耗时。

混合检索剩余漏检为T02图案防水、T05款式区别、T07不存在的组合、T10收伞教程和T17换货人工边界。T02字面检索能够命中K03，融合后却被商品条目挤出前3；T07的商品条目也挤占了说明不存在组合的知识。T10两路均未在前3找到K12。这里只记录观察，未为了这轮题修改知识、增加专用词典或调整排序参数。下一轮应分别检查知识表达、重复商品候选占位、关键边界是否被保留，以及人工规则如何独立执行。

余弦最高分在18道相关题中为0.480520—0.788059，在5道纯无关题中为0.387792—0.422153。开发题上的0.45门槛恰好能挡住这5道无关题，但这不构成上线阈值：额外6道与伞有关的资料缺口诊断题G01—G06（直径、重量、收起长度、伞柄材料、个案物流单号、实时库存）全部有语义候选，最高分为0.489629—0.633243，均超过0.45。伞柄材质最相似的是不锈钢**伞骨**知识，仍不能将它当成伞柄材料；相似度也不能生成真实订单或库存数据。

G题只用于诊断，未混入18道开发题的召回指标，不是独立保留集。候选资料可以帮助说明缺口，但不能提供这些具体值。`--evaluate` 会记录分数范围和多个门槛的误挡/漏挡情况，`--diagnose-gaps` 会额外记录G题候选；没有自动选定门槛，也没有实现自动拒答。当前所有方法仍标记 `sufficiency=unvalidated`，融合分数仅用于排序。

扩展后12项独立测试通过，新增检查覆盖融合去重、不同分数尺度、单路为空、两路依据合并、参数范围和阈值诊断，未连接数据库或付费接口。聊天功能尚未改动。下一步先讨论如何检查回答所需事实是否存在，再决定知识表达或排序的改进方案。
